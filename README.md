# IdeaDNA — The Living Ideas Network

A Next.js application for collaborative invention trees. Includes an interactive React Flow workspace, branching and revision history, discovery, profiles, network analytics, Supabase authentication/realtime/storage, and server-only AI synthesis.

## Run the demo

Requirements: Node.js 22.13+ (Node 24 recommended) and npm.

```sh
npm ci
npm run dev
```

Open http://localhost:3000. Without Supabase environment variables, the application runs in a clearly marked demo mode. Three sample trees, four sample contributors, and 24 contributions are available. Creating, editing, archiving, and reacting work locally; trees and revisions are stored in this browser. Accounts, shared realtime updates, avatar uploads, and AI generation require the connected setup below. Sample synthesis blueprints are readable in demo mode; generated AI output is never simulated.

## Connect a Supabase workspace

1. Create a Supabase Free project. In its SQL editor, run `supabase/migrations/202610220001_core.sql` **once**. The project already provides `auth`, `storage`, API roles, and the `supabase_realtime` publication.
2. For a demonstration project only, run `supabase/seed.sql`. It creates sample users with unknown random passwords; they cannot be used as shared login accounts. Create your own account through `/signup`. Do not seed production with demonstration users.
3. Copy `.env.example` to `.env.local`. Fill `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` from Project Settings → API. The publishable/anonymous client key is intended for the browser. Keep RLS enabled.
4. Fill `SUPABASE_SERVICE_ROLE_KEY` with the project's server secret/service-role key. This key is used only in the synthesis completion route. Do not prefix it with `NEXT_PUBLIC_`, paste it into the UI, or commit it.
5. In Authentication → URL Configuration, set Site URL to `http://localhost:3000` and allow `http://localhost:3000/auth/callback`. Enable the Email provider. For email confirmation, use the confirmation link generated by Supabase; the callback exchanges its authorization code for a session. In custom email templates, retain Supabase's `ConfirmationURL` link.
6. Configure an AI provider as described below, restart the dev server, and create your own account. Public trees can be read anonymously; writes and synthesis require sign-in. `/settings` and `/trees/new` are protected when Supabase is connected.

### Local Supabase alternative

With Docker running and the official Supabase CLI installed:

```sh
supabase start
supabase db reset
supabase status
```

`db reset` is destructive to the **local** database; use it only for disposable development data. The checked-in config applies the migration and seed. Copy the local URL, anonymous key, and service-role key into `.env.local`. Local email confirmation is disabled by the development config. Hosted production should enable confirmation.

## AI providers

Set `GROQ_API_KEY` for the default provider. The current default model is `openai/gpt-oss-120b`; override with `GROQ_MODEL` for another model available to your account. Groq retired Llama 3.1/3.3 from its free/developer tiers on August 16, 2026, so the original brief's Llama 3 default is no longer viable. See https://console.groq.com/docs/deprecations.

Set `GOOGLE_GENERATIVE_AI_API_KEY` for optional Gemini fallback, or leave Groq blank to use Gemini alone. `GEMINI_MODEL` defaults to `gemini-3.1-flash-lite`. Model availability and free quotas can change; select a model available on your provider's free tier. The application never enables billing or upgrades a plan.

`POST /api/synthesize` accepts:

```json
{
  "tree_id": "UUID",
  "source_node_a_id": "UUID",
  "source_node_b_id": "UUID",
  "intent": "Design an off-grid pilot"
}
```

Both nodes must be distinct, published, readable nodes in the same tree. The server validates inputs, reserves one of eight requests per user per hour under a database lock, calls Groq (then Gemini if configured and needed), validates the blueprint with Zod, and commits the node, both edges, and completed request in one transaction. Failed requests remain recorded. Timeouts are bounded to fit the route's 60-second duration. An exhausted free-tier quota returns an error; no paid fallback exists.

AI blueprints include the concept, problem, mechanism, components, complementary strengths, conflicts, risks, and a next contribution. Treat them as proposals requiring verification.

## Database and security

- Six requested entities plus immutable `node_revisions`.
- PostgreSQL enums, foreign keys, partial root uniqueness, indexes, timestamp triggers, auth-to-profile trigger, RLS, and storage policies.
- Public trees are discoverable. Unlisted trees are readable by link and excluded from Explore; unlisted URLs are not a confidentiality boundary. Private trees are visible only to their creator. The tree directory also includes a signed-in user's own private/unlisted trees.
- Public profiles expose name, username, bio, and avatar, never email.
- Contributors can edit/archive their own nodes; tree creators can edit/archive nodes in their tree. Updates preserve original attribution and append the previous title/content/status to revision history.
- Clients have narrow column grants. They cannot assign authorship, change topology, inflate scores, or mark synthesis complete. Creation RPCs derive the actor from `auth.uid()`.
- The service-role client is used only after authenticated source authorization, and only to commit the reserved synthesis. Its RPC is not executable by browser roles.
- Reaction scores are derived by a database trigger; the reaction tuple is unique.
- Realtime subscriptions reload authorized data on node/tree/reaction/synthesis events.
- Avatar storage allows only images under 2 MB in the authenticated user's folder.
- Mutations check request origin, use bounded request bodies, and validate with Zod. AI inputs are treated as untrusted text and output is rendered as text.

## Pages and APIs

`/`, `/login`, `/signup`, `/explore`, `/trees`, `/trees/new`, `/trees/[slug]`, `/trees/[slug]/node/[nodeId]`, `/profile/[username]`, `/dashboard`, `/settings`, `/privacy`, `/terms`, `/auth/callback`.

`GET/POST /api/trees`; `GET/POST/PATCH /api/ideas`; `POST /api/synthesize`.

In the graph: click a node to inspect/select it, select two for synthesis, double-click to contribute, use a node's minus/plus control to collapse/expand descendants, or use search/type/contributor filters. Keyboard users can Tab to a contribution and press Enter/Space to inspect/select it. Fit, zoom, and minimap are supplied by React Flow. Graph positions are deterministic by depth and peers; larger trees remain navigable with zoom, search, collapse, and the minimap.

## Validation

```sh
npm run typecheck
npm test
npm run build
```

Database tests execute the migration in an embedded PostgreSQL engine with minimal Supabase auth/storage fixtures. They cover permissions, private trees, cross-tree constraints, transactional creation, revisions, reaction scores, synthesis privileges, dual edges, and rate limits. This does not replace a hosted Supabase integration check for Auth email delivery, Storage HTTP, and Realtime transport. AI calls need real provider keys and were not exercised without credentials.

The project uses Next.js's supported Webpack compiler. Turbopack's CSS worker failed on the development Windows host; Webpack production compilation succeeds.

## Structure

- `src/app`: App Router pages, API routes, loading/error boundaries.
- `src/components`: application shell, discovery, profile, tree workspace, and shadcn-style Radix/CVA button primitive.
- `src/hooks/use-ideas.ts`: demo persistence or authenticated Supabase data and realtime lifecycle.
- `src/lib/supabase`: browser, cookie-bound server, and server-only admin clients.
- `src/lib/ai`: provider orchestration and blueprint validation.
- `src/lib/validations`: bounded schemas.
- `supabase`: migration, seed, and local config.
- `tests`: PostgreSQL policy and validation checks.

Tailwind v4 is configured with a tokenized custom component layer. `components.json` supports adding shadcn/ui components. Framer Motion and TanStack Query are intentionally omitted: CSS handles short transitions, and a single realtime-aware data hook handles the current query needs.
